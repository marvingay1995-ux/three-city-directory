# Codex Instructions — Three-City Directory

## Project
Repository: marvingay1995-ux/three-city-directory
Purpose: general local business directory for Dubai, Muscat and Doha.
Source of truth: docs/PRODUCT_VISION.md, docs/PRD.md, docs/DESIGN_SYSTEM.md, docs/ARCHITECTURE.md, docs/IMPLEMENTATION_PLAN.md, docs/ACCEPTANCE_CRITERIA.md.

## Mandatory operating rules
1. Inspect main and existing code before editing. Preserve existing functionality.
2. Execute only the assigned phase. No scope expansion without approval.
3. Create an isolated branch and PR targeting main; never merge or push directly to main.
4. No deployment, hosting setup, public preview, credentials, external services, paid tools, tracking, or payments.
5. No real listings, real individuals, real business contact data, user onboarding, booking, direct messaging, or live advertising.
6. Demo content must be unmistakably fictional. Avoid legally sensitive/regulated categories.
7. Do not scrape websites or import third-party content.
8. Validate city scoping and all input; prioritize accessibility, security, privacy and testability.
9. Run npm test, npm run typecheck, npm run build; report actual outcomes. Do not claim checks passed if not run.
10. Document changed files, risks, assumptions, screenshots for UI work, and exact PR URL.
11. Stop and ask for approval before architecture changes requiring external infrastructure, new credentials, legal review, spend or production enablement.
12. The user owns merges and release decisions.

## First assignment
Follow Phase 0 in docs/IMPLEMENTATION_PLAN.md: reconcile current main and Foundation 001/002, execute baseline checks, fix only necessary blockers on an isolated branch, and open a PR with evidence. Do not begin Phase 1 until authorized.

## Acceptance
Use docs/ACCEPTANCE_CRITERIA.md for each phase. A successful CI run does not authorize a public deployment.
