# A11Y-001 — Responsive and keyboard acceptance (private prototype)

## Automated coverage

The real Chromium DevTools Protocol script `tools/interactive-acceptance.mjs` now exercises the homepage, Muscat directory and a Muscat detail page at widths **320, 375, 390, 768, and 1024 pixels**. The checks measure actual document overflow, presence of the fictional-content disclosure and basic visibility of keyboard controls. It also sends real Tab and Enter key events on a profile page, checks `:focus-visible` styling and activates the skip-to-main link.

Existing gallery switching, sorting, comparison and ephemeral selection regressions remain enabled. Generated `interactive-checks.json` is retained inside the private 14-day Actions artifact.

## Meaning and limits of results

Passing these checks establishes only that the selected routes under the tested local Chromium environment satisfy the specified assertions. This is **not** a WCAG certification, nor a test of all browser/OS combinations, orientation, font scaling, language direction, touch targets or zoom. A failed check must be investigated as a possible genuine defect, not hidden.

A human accessibility pass is still required for:
- Keyboard focus order across all controls, including two-profile comparison after rerender, gallery controls and filters.
- Screen reader heading/landmark navigation, results/status announcements and comparison table reading.
- High-contrast, 200%/400% zoom, reduced motion and variable text scaling.
- Touch target size and text/interactive contrast against the final rendered colour palette.
- Actual mobile devices and browsers, not only emulated widths.
