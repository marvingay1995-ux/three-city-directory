# SEC-001 — PostCSS transitive dependency remediation

Status: **dependency patch verified in Node 22 CI; independent security sign-off still pending**. Live launch remains **NO-GO** in Dubai, Muscat and Doha. Linked to Issue #19 and Phase 6 G2.

## Baseline and scope
On 2026-11-18 the Phase 6 evidence reported `npm audit --json` exit 1. The lockfile contained Next.js 15.5.29 pinning a transitive PostCSS 8.4.31. Reported high-severity PostCSS advisories were GHSA-qx2v-qp2m-jg93, GHSA-6g55-p6wh-862q, GHSA-fxqj-rqcc-2cmp and GHSA-r28c-9q8g-f849, with a related moderate Next.js dependency-chain entry. The report did not establish public exploitability. See `docs/launch-readiness/security.md` for original evidence.

## Controlled change

| Dependency | Before | After / action |
| --- | --- | --- |
| Next.js | 15.5.29 | **15.5.29 unchanged** |
| PostCSS | 8.4.31 (Next transitive pin) | **8.5.23**, explicitly overridden in `package.json` |
| React / React DOM | 19.3.1 | unchanged |
| Other direct dependencies | baseline lockfile | unchanged |

A narrow npm `overrides.postcss` constraint selects patched PostCSS without a major Next.js upgrade. The npm lockfile is **generated by npm**, not manually fabricated: the short-lived Node 22 CI lockfile generation step ran `npm install --package-lock-only --ignore-scripts --no-audit --no-fund` successfully, then `npm ci`, tests, typecheck, build and loopback HTTP regressions succeeded. That temporary CI step was removed after its exact emitted lockfile was committed. The resulting lockfile records PostCSS 8.5.23 with integrity `sha512-g50586zr4bZmwFiTlflMu8E0bDTb5I5gertgwAKmsdUlTQIhZtunzUlD1WSzwcVWPoAVpsrA6vlfCD7oXvRwgg==`.

**Important compatibility caveat:** An override changes a Next.js pinned transitive. Successful CI exercises the current demo and does not by itself establish full compatibility across untested Next.js CSS build paths. A supported upstream Next.js dependency path remains preferable if an equivalent patch becomes available; release security must verify the package maintainer's supported range, effectiveness and applicability.

## Verification and audit gate
CI now executes `npm audit --audit-level=high` after clean install. This fails on high/critical findings without suppressing moderate findings; remaining moderate issues must be inventoried separately with a full `npm audit --json` report. Audit registry access is essential: an unavailable registry is **not** a passing audit.

Repeat locally and in Node 22 CI:
```sh
node --version
npm ls next postcss
npm ci --no-audit --no-fund
npm audit --json
npm audit --audit-level=high
npm test
npm run typecheck
npm run build
# Existing CI also starts only a loopback server and executes tests/profile-http.mjs.
```

Record exact CI job evidence and post-fix audit details on the PR. A zero-exit high-level threshold can coexist with non-high advisories and does **not** mean a vulnerability-free dependency graph.

## Release blockers retained
- Confirm all prior advisory IDs are absent or independently evaluated in a fresh full audit.
- Validate PostCSS/Next compatibility and build-time/runtime reachability with an independent security reviewer.
- Independently review current Next.js and other dependency advisories, including any moderate findings; document disposition, owners and expiry for accepted exceptions.
- Keep G1–G6 of Phase 6 open pending independent legal, privacy, security, accessibility, operations and explicit owner authorization.

No deployment, upgrades of major framework versions, real advertisers, data collection, payments, analytics or infrastructure provisioning are authorized.
