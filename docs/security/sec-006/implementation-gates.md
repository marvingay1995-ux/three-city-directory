# Proposed implementation sequence and approvals

Each numbered package below is conditional on a **separate written product-owner authorization and a named scoped reviewer**. This document authorizes none. Do not use the package list as approval to start SEC-007. Exact paths are suggested boundaries for subsequent scoped PRs. Any proposed expansion needs approval before work.

| Package / dependency | Candidate file and surface limits | Acceptance and stop condition |
| --- | --- | --- |
| 1. Freeze contracts and testable invariants (after SEC-006 review) | Documentation in a new security design folder only. No app, environment or dependency changes. | Signed scope and reviewed auth, transaction, privacy and threat contracts. Stop on ambiguous roles, unclear visibility invariants or unresolved architecture constraints. |
| 2. Approve ADR and decision evidence (after 1) | Approved decision record and written review package. No account, vendor, region, pricing commitment or credentials. | Owner decision with IAM, Data, Privacy and Security reviewers, country-flow prerequisites and option reversal criteria. Stop on missing independent advice or an unknown lawful flow. |
| 3. Isolated synthetic transaction proof (after 1–2 and authorization) | Test-only folders and scoped synthetic model/test files. No public application imports, network, provisioning or real data. Any need for a real engine or service requires a new authorization. | Deterministic concurrency, CAS, audit/outbox/replay and restore evidence under declared assumptions. Stop on partial commits, unsafe replay, scope failure or unverified recovery. |
| 4. Authorized private integration (after 3 and separate design/privacy/security approval) | Only explicitly named protected adapters, schema/migration, worker and test surfaces in an approved access-controlled environment. Vendors, credentials, test infrastructure and data classification must be separately scoped first. | End-to-end checks with synthetic data and independent review of access, privacy, migration and outage controls. Stop on boundary changes, data leakage or unapproved external dependency. |
| 5. Independent verification (after 4) | Evidence, agreed private test targets and scoped fixes only. Written environment, methods, rollback and data restrictions. | Qualified independent security assessment of the exact artifact and regions, negative tests, remediation/retest and custody/restore attestations. Stop on any launch-blocking issue or missing sign-off. |
| 6. Restricted pilot consideration (after 5 and clearance of all G1–G6 for exact scope) | Only owner-authorized environments, routes, region and users. No implicit ads, payments, tracking or broad release. | Explicit written decision, eligible scope, support and withdrawal/rollback plan. Stop if any gate expires, incident thresholds trigger or supplier, feature or jurisdiction changes. |

Require named owners, evidence, commitments, expiry and rollback on every approval. Future cost estimates are assumptions until staff and vendor rates, usage, incident cover and counsel inputs are independently reviewed. No spend or setup authority follows from the provisional architecture. Keep D-001 NO-GO until all mandatory gates have independent clearance and the owner authorizes exact release scope.
