# SEC-009 invariant assessment

Read the verbatim clauses against the [SEC-007 contracts](../sec-007/README.md), the [SEC-008 evidence index](../sec-008/evidence-index.md) and the actual [SEC-005 tests](../../../tests/security-contracts.test.mjs). **VERIFIED OFFLINE** labels only the cited assertions. All 16 contracts are **PROPOSED**, the production controls are **UNIMPLEMENTED**, and the entire set **REQUIRES INDEPENDENT REVIEW**. The failure cases below describe acceptance criteria for a future authorized candidate.

## Reconciliation findings

- SEC-004 requires verification where applicable. SEC-005 fixtures require verification and make withdrawal terminal. SEC-007 proposes verify-before-publish for the exact reviewed version, with reactivation, affiliate conflicts and transfer controls still open. Keep the stricter candidate pending D7-05.
- The in-process test named “concurrent exact requests replay once and prepared commands detach from caller mutation” is a deterministic schedule. The “across restart” receipt result reloads a synthetic checkpoint. Neither demonstrates engine concurrency, persistence or crash durability.
- Successful audit hashes require an independently trusted anchor. A fixture holding both history and checksum cannot demonstrate segregation, trusted time or resistance to privileged rewriting. P7-02 and P7-04 require different proof.
- Public city route checks use fictional data and sample existing behavior. Private tenancy, refusal timing, worker identities, caches, exports, transfers, trusted time and live IAM remain evidence gaps.
